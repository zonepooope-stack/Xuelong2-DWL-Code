# Xuelong2-DWL: ERA5 collocation and technical-validation code

This repository contains the MATLAB code used to collocate the processed Xuelong2 shipborne Doppler-lidar wind profiles with ERA5 pressure-level data and to generate the code-based panels in Figures 1 and 3-9 of the associated Scientific Data manuscript.

The lidar files, ERA5 NetCDF files, and other large research-data files are not distributed in this code repository. The processed Xuelong2-DWL daily CSV files will be deposited separately in a data repository. ERA5 remains available from the Copernicus Climate Change Service Climate Data Store.

- `run_all_figures.m`: optional batch runner for all code-generated figures.
- `download_era5_pressure_levels.py`: CDS API downloader for the daily ERA5 subsets.
- `build_ship_grid_stay_table.m`: reconstructs the hourly ERA5-grid residence-time table from the released lidar positions.
- `data/era5_request_manifest.csv`: the 166 daily ERA5 request bounds used for the manuscript analysis.

- `NEW_DATASET_VALIDATION.md`: validation record for the cleaned lidar release and code outputs.
- `CODE_AVAILABILITY.md`: manuscript-ready Code Availability template.
- `UPLOAD_GUIDE_CN.md`: Chinese instructions for GitHub and Zenodo publication.

## Software requirements

The scripts were checked using:

- MATLAB R2024b (24.2)
- Mapping Toolbox 24.2
- Statistics and Machine Learning Toolbox 24.2
- Python 3.9 or later with the `cdsapi` package (ERA5 retrieval only)

Map baselayers used by `geobasemap` may require an internet connection on first use unless they are already cached locally.

## Input-data layout

By default, the scripts expect the following local layout:

```text
Xuelong2-DWL-Code_v1.0/
|-- data/
|   |-- ship_grid_stay_all_hours.csv
|   |-- era5_request_manifest.csv
|   |-- era5_hourly_pressure_levels/
|   |   |-- 2023_10_31_part1.nc
|   |   `-- ...
|   `-- lidar_profiles/
|       |-- 20231031 095000.csv
|       `-- ...
`-- outputs/
```

The ERA5 NetCDF files and lidar CSV files are intentionally excluded from GitHub. They may be stored anywhere and referenced through environment variables:

```matlab
setenv('XUELONG2_ERA5_DIR', 'D:\data\era5_hourly_pressure_levels');
setenv('XUELONG2_LIDAR_DIR', 'D:\data\Xuelong2-DWL\data');
setenv('XUELONG2_STAY_FILE', 'D:\code\Xuelong2-DWL-Code-v1.0\data\ship_grid_stay_all_hours.csv');
setenv('XUELONG2_OUTPUT_ROOT', 'D:\results\xuelong2_figures');
```

Alternatively, set `XUELONG2_DATA_ROOT` to a directory containing `era5_hourly_pressure_levels`, `lidar_profiles`, and `ship_grid_stay_all_hours.csv`.

## Retrieving ERA5

Create a CDS account, accept the ERA5 licence on the dataset page, and configure the CDS API client without placing credentials in this repository. Then install the only Python dependency:

```text
python -m pip install -r requirements.txt
```

Inspect a request without downloading data:

```text
python download_era5_pressure_levels.py --start-date 2023-10-31 --end-date 2023-10-31 --dry-run
```

Download all 166 daily subsets into the default input directory:

```text
python download_era5_pressure_levels.py
```

The request manifest reproduces the daily spatial bounds of the ERA5 files used for the manuscript. Fourteen requests cross the antimeridian and therefore have an eastern boundary numerically smaller than the western boundary. Existing files are skipped unless `--overwrite` is supplied.

During the original data preparation, the long ERA5 retrieval was divided among three date-specific scripts to reduce runtime and simplify restarts. Those scripts differed only in their date filters and contained personal local paths. The public release therefore consolidates them into this single parameterized downloader. If separate jobs are preferred, the same historical date blocks can be requested without duplicating code:

```text
python download_era5_pressure_levels.py --start-date 2023-10-31 --end-date 2023-12-31
python download_era5_pressure_levels.py --start-date 2024-01-01 --end-date 2024-02-29
python download_era5_pressure_levels.py --start-date 2024-03-01 --end-date 2024-04-16
```

CDS credentials are read by `cdsapi.Client()` from the user's local CDS configuration and are never stored in the repository.

## Running the code

To rebuild the residence-time table from the released lidar files, first place the daily CSV files in `data/lidar_profiles/` (or set `XUELONG2_LIDAR_DIR`) and run:

```matlab
build_ship_grid_stay_table();
```

The repository includes the resulting `data/ship_grid_stay_all_hours.csv` so that the manuscript analysis can be rerun directly and the regenerated table can be checked against the archived analysis input.

Open MATLAB in the repository directory and run an individual script, for example:

```matlab
run('windband_new.m')
```

To run all code-based figures and write a success/failure table to `outputs/run_status.csv`, use:

```matlab
status = run_all_figures();
```

## Reproducibility conventions

- `hour_start` and lidar `Date_time` values are interpreted as China Standard Time (UTC+8) and converted to UTC for ERA5 matching.
- ERA5 daily files use UTC dates and the filename pattern `yyyy_mm_dd_part1.nc`.
- Wind-speed difference is defined as lidar minus ERA5.
- The four circulation regimes are mutually exclusive.
- The analysis uses lidar measurement heights from 103.9 m to 3000 m. The lowest measured height is reported as 104 m in manuscript text and figures.
- Daytime and nighttime are classified using a solar-elevation threshold of 0 degrees.

## ERA5 source

The code uses *ERA5 hourly data on pressure levels from 1940 to present*, available from the Copernicus Climate Change Service Climate Data Store:

- Dataset: https://cds.climate.copernicus.eu/datasets/reanalysis-era5-pressure-levels
- DOI: https://doi.org/10.24381/cds.bd0915c6
- Variables: zonal wind, meridional wind, and geopotential
- Pressure levels: 1000, 975, 950, 925, 900, 875, 850, 825, 800, 775, 750, 700, 650, 600, 550, and 500 hPa
- Temporal resolution: hourly
- Horizontal grid: 0.25 degrees by 0.25 degrees

The downloaded ERA5 NetCDF files are not redistributed in this repository. The CDS retrieval script and the complete daily request manifest are included so that users can retrieve the required subsets from the source service.
